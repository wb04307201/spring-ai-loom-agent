# 子系统 #2 — 聊天核心 E2E 剧本

**目标**: 验证聊天 SSE 流 + 工具触发 + 子任务分发 + 边界(空 / 长 / 中断 / thinking)
**前置**: Task 0 fixture 完成 + Task 1 admin 登录完成(cookie 持久)
**预计 wall clock**: 20 min

---

## Smoke 用例: index.html 加载

**步骤**:
1. (admin 已登录) `navigate_page` pageId type=url url="http://localhost:8080/index.html"
2. wait_for pageId text=["chat input", "发送", "请输入消息"]
3. take_snapshot
4. list_console_messages pageId types=["error"] → 断言 0 个 error
5. 截图

**断言**:
- chat input 可见
- 工具栏可见
- 侧栏/历史入口可见
- console 0 error

**截图**: `docs/notes/browser-baselines-2026-10-01/02-chat/chat-baseline.png`

## E2E-1: 「你好」 → 完整中文响应

**步骤**:
1. fill chat input "你好"
2. click 发送
3. **SSE 超时检测**: list_network_requests 监听 `/spring/ai/loom/api/chat`,轮询 90s,直到见 `data: [DONE]` 或 `event: done`
4. wait_for pageId text=["你好", "您好", "你好!"]
5. take_snapshot → 断言响应可见 + 中文 + 含 emoji 或能力清单
6. 截图

**断言**:
- 完整中文响应
- 90s 内 SSE 完成
- 含 emoji 或能力自述

**截图**: `docs/notes/browser-baselines-2026-10-01/02-chat/hello-response.png`

---

## E2E-2: 「现在几点」 → 触发 tool_time(全深度验证)

**步骤**:
1. fill "现在几点"
2. click 发送
3. SSE 检测(同上)
4. take_snapshot → 断言响应含时间字符串 + 工具调用折叠区
5. evaluate_script → 检查 `loom_tool_call_log` 通过 GET API 或展开 chat log
6. **深度断言**:
   - 响应含「2026 年 / 10 月 / 01 日 / HH:MM」格式
   - LLM 在响应末尾主动建议「定时任务 / 时区转换」(基于 system prompt【平台能力】)
7. 截图

**断言**:
- 工具正确触发(查 tool_call_log)
- 时间格式正确
- 主动建议能力

**截图**: `docs/notes/browser-baselines-2026-10-01/02-chat/time-tool-triggered.png`

## E2E-3: 「Python 排序列表」 → LLM 不拆子任务

**步骤**:
1. fill "用 Python 写个快速排序"
2. click 发送
3. SSE 检测
4. take_snapshot → 断言:
   - chat 流中**无 sub-task chip**(不拆)
   - 响应含 Python 代码块
5. 截图

**断言**:
- 不触发子任务(简单任务)
- 给出代码

**截图**: `docs/notes/browser-baselines-2026-10-01/02-chat/python-no-subtask.png`

## E2E-4: 「调研 AI 行业」 → 拆 3 个并行子任务(全深度验证子任务分发)

**步骤**:
1. fill "调研 2026 年 Q3 全球 AI 行业最新进展"
2. click 发送
3. SSE 检测(注意子任务会让响应变长,可能 60-120s)
4. take_snapshot → 断言:
   - chat 流中**至少 2 个 sub-task chip**(⏳ PENDING → RUNNING → COMPLETED)
   - chip 含 ID / 计时 / prompt 预览
5. click chip 展开 → 检查 detail 面板含完整 prompt
6. wait_for chip 全部变 COMPLETED(最长 600s,含子任务 600s 超时防御)
7. 截图

**断言**:
- LLM 自主拆 ≥2 个子任务
- 完整生命周期轮转
- 主对话接收所有子任务结果

**截图**: `docs/notes/browser-baselines-2026-10-01/02-chat/parallel-subtasks.png` + `subtask-detail.png`

## E2E-5(边界): 长 prompt(>2000 字符)→ 不截断

**步骤**:
1. evaluate_script 生成 2000+ 字符字符串,含中英文 / 换行 / emoji
2. fill chat input 该字符串
3. click 发送
4. SSE 检测
5. take_snapshot → 断言:
   - 响应非空(LLM 处理了完整 prompt)
   - **无截断提示**(如"消息过长已截断")
6. 截图

**截图**: `docs/notes/browser-baselines-2026-10-01/02-chat/long-prompt.png`

   - 行为 = noop(无 SSE 请求) / 显示「请输入消息」 / 按钮 disabled
4. console 0 error
5. 截图

**截图**: `docs/notes/browser-baselines-2026-10-01/02-chat/empty-message.png`

## E2E-7(边界): 流中断(网络中断 30s)

**步骤**:
1. fill "讲一个长故事"
2. click 发送
3. **30s 后** evaluate_script → `() => { window.dispatchEvent(new Event('offline')); navigator.onLine = false; }` 或通过 DevTools emulate network offline
4. 观察 chat 流表现
5. 60s 后恢复:`emulate networkConditions online` 或 `navigator.onLine = true`
6. take_snapshot → 断言:
   - 流中断不导致页面崩溃
   - 恢复后能继续聊天
7. 截图

**截图**: `docs/notes/browser-baselines-2026-10-01/02-chat/network-interrupt.png` + `network-recover.png`

## 失败处理

- 整剧本 3 次重试
- E2E-1/2/4 失败 = CRITICAL(聊天核心)
- E2E-3 失败 = MAJOR(子任务决策错误)
- 边界 E2E-5/6/7/8 失败 = MAJOR/MINOR
- SSE 90s 超时 → 标 TIMEOUT
