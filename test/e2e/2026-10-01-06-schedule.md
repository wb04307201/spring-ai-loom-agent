# 子系统 #6 — Schedule 短间隔触发 E2E 剧本(上轮 P3)

**目标**: 验证 ⏰ 定时任务创建 → 短间隔 10s 触发 → 状态机轮转 → 取消 → 持久化(上轮未跑实际触发)
**前置**: Task 0 + Task 1 完成
**预计 wall clock**: 15 min(含实际等待 10s 触发 × 2 轮)

---

**步骤**:
1. (admin 登录 chat) 找到 ⏰ 定时按钮(具体位置查 UI)
2. click 按钮
3. take_snapshot → 断言:
   - 创建表单弹出(任务名 / 触发 prompt / 间隔 / cron / ...)
4. 截图

**断言**:
- 按钮可达
- 表单元素完整

## E2E-1: 创建短间隔(10s)schedule → 等待触发(上轮 P3 深度)

**步骤**:
1. fill 表单:
   - name="测试定时 10s"
   - prompt="说一声 hello,确认定时任务触发"
   - interval=10s(或 cron 等价)
2. 提交
3. take_snapshot → 断言创建成功,任务列表显示状态 SCHEDULED
4. **轮询触发**:
   - 每 5s 调 `fetch('/spring/ai/loom/api/schedule/list')` 检查 status
   - 最长等 60s
   - 断言: status 进入 RUNNING → COMPLETED
5. take_snapshot → 截图最终状态
6. (chat 流中应收到触发的子任务或新消息)
7. 截图

**断言**:
- 短间隔实际触发(不是仅创建不触发)
- 状态机完整

**截图**: `docs/notes/browser-baselines-2026-10-01/06-schedule/schedule-created.png` + `schedule-triggered.png`

## E2E-3: cancel_schedule → 状态变 CANCELLED + 不再触发

**步骤**:
1. 创建新 schedule "测试定时 5s cancel":
   - name="测试定时 cancel"
   - interval=5s
2. 提交 → 确认 SCHEDULED
3. 调 cancel 端点(fetch API 或 UI 按钮)
4. 等待 15s(应触发 3 次,但 cancel 后只触发 0-1 次)
5. fetch API → 断言 status=CANCELLED
6. 查触发历史 → 断言触发次数 ≤ 1
7. 截图

**断言**:
- 取消生效
- 不再触发

**截图**: `docs/notes/browser-baselines-2026-10-01/06-schedule/schedule-cancelled.png`

## E2E-7(边界): 跨重启持久化

**步骤**:
1. 创建 interval=600s 的 schedule "测试重启持久化"
2. 确认 SCHEDULED
3. **重启服务**:
   ```bash
   kill $(pgrep -f 'spring-boot:run')
   export JAVA_HOME="/c/Program Files/Java/jdk-25.0.3"
   nohup mvn spring-boot:run -pl spring-ai-loom-agent-test -Dgpg.skip=true \
     > /tmp/mvn-restart.log 2>&1 &
   for i in $(seq 1 90); do
     curl -sf http://localhost:8080/spring/ai/loom/api/features > /dev/null && break
     sleep 2
   done
   ```
4. 重新登录(admin)
5. fetch schedule list → 断言「测试重启持久化」仍在,status 仍 SCHEDULED
6. cancel 清理
7. 截图

**断言**:
- 重启不丢失 schedule
- `loom_scheduled_task` 持久化生效

**截图**: `docs/notes/browser-baselines-2026-10-01/06-schedule/schedule-restart-persist.png`
