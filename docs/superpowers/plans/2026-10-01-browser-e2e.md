- **JDK**: 必须用 `JAVA_HOME=/c/Program Files/Java/jdk-25.0.3` (pom `--release 25`,默认 jdk-17 不支持) — Bash 命令前 export

- **失败重试**: 整剧本 3 次重试,3 次仍 fail 标 fail 继续下一个

## Review Focus

(基于 spec,但不被 task 测试覆盖的输入/失败模式):

1. **LLM 流式响应中断**: SSE 流 `event-stream` 中途断流(`event: done` 缺失)→ 现有 task 假设完整流,需要在 Task 02 (chat.md) 加超时检测:`list_network_requests` 监听 `/spring/ai/loom/api/chat`,若 90s 内未收到 `[DONE]` 标记 → 标 fail
2. **MCP server 启动慢导致 npx 进程堆积**: `mcp-servers.json` 4 个 npx MCP server 启动可能 >30s,在 Task 03 (rbac-tool.md) 加保护:单 MCP server 超时 → 跳过该工具,继续其他
3. **Window respawn cookie 失效**: 长 session 后 Chrome cookie 失效(可能 systemd 清理)→ Task 00 (fixture) 后立即 snapshot cookie,后续 task 失败时先验证 cookie 还在
4. **Sub-task 600s 超时防御**: 子任务超时 → 主对话流被截断(Task 05),需要在 Task 05 加防御:触发后立即记录 start_time,若 chip 60s 内仍 PENDING → cancel + 标 fail
5. **Schedule 短间隔实际触发**: 10s 间隔 schedule 创建后,触发可能延迟到下个周期 → 轮询间隔 5s,最长 60s
6. **画板 PNG 导出无 lib 验证**: 不验证 PNG 像素内容,只验证 chat 流是否收到附件 + 预览按钮可见
7. **审批流需要 2 个 user**: admin submit 审批 → 普通 user 浏览/或反之 → 提前创建 test-user-1 + test-user-2(setup 阶段)
8. **对话历史需预生成数据**: 跑子系统 #10 前需有 3-5 轮历史对话(setup 阶段由子系统 #2/5 自动产生)

每个 task 的 step 中已包含对应防御。spec §7.2 失败分类表 + §8 验收标准。
