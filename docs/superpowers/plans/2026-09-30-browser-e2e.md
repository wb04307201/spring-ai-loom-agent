## Global Constraints

- **JDK**:必须用 `JAVA_HOME=/c/Program Files/Java/jdk-25.0.3`(pom `--release 25`,默认 jdk-17 不支持)— Bash 命令前 export
- **Chrome DevTools MCP**:仅主对话 driver 可用,subagent 拿不到 — **绝对不能 dispatch subagent 跑 Chrome 操作**
- **真实 LLM 调用**:项目 yml 配 Anthropic 兼容(`/apps/anthropic`),不允许 mock — 接受 ~$0.5-2 API 费 + 偶发超时(3 次重试)
- **数据库**:`~/.loom/datasource/` + `spring-ai-loom-agent-test/target/test-ds`(CLAUDE.md「浏览器 IT 隔离约定」)
- **视觉 baseline**:首次跑生成 `docs/notes/browser-baselines-2026-09-30/` 初始 PNG,**不对比**(下次跑才 diff)
- **单 page 复用**:8 个子系统测试**复用同一 Chrome page**(不重启 Chrome),Cookie 跨子系统持久
- **失败重试**:整剧本3 次重试,3 次仍 fail 标 fail 继续下一个
- **CRITICAL 失败中止**:CRITICAL 类(登录/聊天核心不可用)= 0 → abort 后续子系统 + 紧急报告

## Review Focus

(基于 spec,但不被 task 测试覆盖的输入/失败模式):

1. **LLM 流式响应中断**:SSE 流 `event-stream` 中途断流(`event: done` 缺失)→ 现有 task 假设完整流,需要在 Task 3 (chat.md) 加超时检测:`list_network_requests` 监听 `/spring/ai/loom/api/chat`,若 60s 内未收到 `[DONE]` 标记 → 标 fail
2. **MCP server 启动慢导致 npx 进程堆积**:`mcp-servers.json` 4 个 npx MCP server 启动可能 >30s,在 Task 4 (rbac-tool.md) 加保护:单 MCP server 超时 → 跳过该工具,继续其他
3. **Window respawn cookie 失效**:长 session 后 Chrome cookie 失效(可能 systemd 清理)→ Task 2 (fixture) 后 立即 snapshot cookie,后续 task 失败时先验证 cookie 还在
4. **Sub-task 600s 超时防御**:子任务超时 → 主对话流被截断(Task 5),需要在 Task 5 加防御:触发后立即记录 start_time,若 chip 60s 内仍 PENDING → cancel + 标 fail

每个 task 的 step 中已包含对应防御。spec §7.2 失败分类表 + §12 验收标准。
